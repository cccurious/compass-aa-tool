# 【仕様書】#コンパス チャットアスキーアート（AA）自動変換ツール

（2026-07-24 ユーザー提供の分析仕様。数値は実機校正前の推定値を含む）

## 1. プロジェクト目的

スマホゲーム『#コンパス』のゲーム内チャットにおいて、自動改行（Auto Wrap）の挙動のみを利用して意図した形状のアスキーアート（AA）を出力するためのテキスト自動調整（スペーサー付与）ツールを開発する。

## 2. システム環境と主要制約

- **描画エンジン:** Unity（Text / TextMeshPro コンポーネント）
- **改行コード制限:** チャット入力では改行（`\n`）が不可。
- **レイアウト制御手法:** 1行の最大ピクセル幅に達すると自動改行される仕組みを利用し、各行の末尾に「見えないスペース（全角・半角スペース）」等を詰めて文字を次の行へ押し出す。
- **フォント仕様:** プロポーショナルフォント（可変幅）を採用。
  - ※近年 LETS フォントから変更されており、`Noto Sans JP` などのオープンソース系＋欧文フォント（フォールバック）で構成されている可能性が高い。

## 3. 分析データから判明した表示法則（仕様詳細）

### ① 1行の限界幅

- 1行の最大横幅は **「全角約20.5文字分」**（ピクセル固定値）。
- 全角文字（幅1.0）だけの場合、20文字では改行されず、21文字目で改行される。そのため「全角20文字 ＋ 半角スペース1つ（幅0.5）」の **合計20.5** が改行のしきい値となる。

### ② キャリーオーバー（溢れ出し）現象

- 1行の限界幅（20.5）を超えて挿入されたスペースや文字は、そのまま次の行の行頭インデント（左端の余白）として押し出される。
- AA全体のドット単位のズレや斜め線の角度調整は、「前行からあふれ出させたスペース量」によって制御されている。

### ③ プロポーショナル幅の利用

- 半角スペース（約0.5）だけでなく、半角記号（`,`, `;`, `\`, `₁` など）はさらに狭いピクセル幅（約0.2〜0.3）を持つ。
- これらを文字幅調整用パーツ（スペーサー）として利用することで、0.1文字単位の精密なレイアウト調整が可能。

## 4. 推奨されるアルゴリズム方針

1. **フォントのピクセル幅テーブル作成**
   - 使用フォント（`Noto Sans JP`等）に基づき、各文字の描画ピクセル幅（Advance Width）を取得・定義する。
2. **行ごとの文字幅計算とスペーサー自動挿入**
   - 入力されたコンテンツ行の文字幅和を計算。
   - 目標幅（20.5文字分＝指定ピクセル幅）に達するまで、行末に最適な「全角スペース / 半角スペース / 調整用記号」の組み合わせを自動付与する。
3. **キャリーオーバー（持ち越し）幅の計算**
   - 超過した幅を次行の初期幅（オフセット）として加算し、連続する行のレイアウトを破綻させずに維持する。

## 5. 開発時の注意事項・ハマりどころ

- **Word Wrap（単語区切り）の誤発動**
  - 半角英数字や特定記号が連続すると、Unityの単語ハイフネーション機能が働き、スペースの位置まで巻き戻って意図しない改行が発生する。
  - 対策: 全角文字・全角記号、またはWord Wrapを発生させない日本語文字・特殊記号をベースに構成すること。
- **端末・解像度の依存性検証**
  - UnityのUIキャンバス設定（Canvas Scaler）により、基本的に端末画面サイズが変わってもチャット吹き出しのピクセル幅比率は維持される想定だが、実機検証（iOS/Android）が必要。
- **特殊記号のフォールバック注意**
  - 欧文記号（`©`など）や一部の特殊な絵文字・下付き文字は、フォントのフォールバック（別フォントへの切り替え）が発生し、意図しないスケールや文字幅変化を引き起こす可能性がある。

- 優先端末: スマホ
- 検証データ: 入力と結果のペアあり（iPhone）。追加採取可能
- チャットの入力可能文字・文字数上限: 未検証（校正フェーズで実機確認）
