# 幅テーブル校正計画（フォント逆算ルート）

作成: 2026-07-25 ／ 方針確定: フォントを特定し、フォントファイルの Advance Width から
幅テーブルを逆算する。実機データ（入力文字列＋iPhone スクショのペア）は
折り返し位置を「オラクル（正解判定器）」として使う。

## 原理

- 実機の折り返し位置は幅の不等式を与える:
  k 文字目で折れた ⇔ `Σw(1..k-1) ≤ LIMIT < Σw(1..k)`
- ピクセルを測らなくても、設計したプローブ文字列の折り返し位置だけで
  フォント仮説（＝幅テーブル予測）の合否を機械判定できる。
- フォントが確定すれば `hmtx` テーブルから全文字の幅が em 単位で得られ、
  実測が必要なのはスケール係数のみになる。
- TextMeshPro は字間（tracking）が加算されうるため、フィットは
  `実効幅 = a × AdvanceWidth + b` の線形モデルで行う（b=0 が理想）。

## フェーズ A: しきい値と基本幅の確定（最優先・4 枚）

以下を 1 メッセージずつ送信し、スクショを撮る。
（□ は送信文字列。全部コピペで使える。行末スペースに注意）

1. `あ` ×20 — 予想: 折り返しなし
```
ああああああああああああああああああああ
```
2. `あ` ×21 — 予想: 21 文字目で折り返し
```
あああああああああああああああああああああ
```
3. `あ` ×20 ＋半角スペース＋`い` — 予想: `い` だけ 2 行目（スペース幅=0.5 の確認）
```
ああああああああああああああああああああ い
```
4. `あ` ×20 ＋半角スペース×2 ＋`い` — 予想: 3 との差分でスペースの行末トリム有無を判定
```
ああああああああああああああああああああ  い
```

## フェーズ B: フォント指紋（2 枚）

5. 字形識別用（できるだけ画面を拡大して撮影）:
```
永愛鬱骨アグ直入
```
6. 欧文・記号のフォールバック判定用:
```
Rag17&@%タゾ
```
→ 候補フォント（Noto Sans JP / Source Han Sans / M PLUS 1p / M PLUS Rounded 1c 等）と
字形を照合。並行して 5・6 の折り返し位置は使わない（短いので）。

## フェーズ C: 半角・記号の幅プローブ

対象文字 c の幅は「`あ`×n ＋ c×m ＋ `い`」の折り返し位置で挟み撃ちにする。
例（半角カンマ: 20 + 0.3×k が 20.5 を跨ぐ点を見る）:
```
ああああああああああああああああああああ,い
```
```
ああああああああああああああああああああ,,い
```
→ 対象文字と本数の組はフォント仮説確定後に「予測の白黒が付く組み合わせ」だけを
生成して依頼する（総当たりしない）。

## フェーズ D: 使用可否（省略表示）の一括検証

候補記号を全角で挟んで 1 メッセージにまとめ、消えた文字を 1 枚で判定:
```
あ,あ;あ\あ`あ^あ|あ~あ・あ、あ。あ
```
- 消えた文字＝使用不可。スペーサー候補から除外（幅 0 になり計算を壊すため）。
- 表示された文字のみ `metrics.ts` の `verified: true` に昇格できる。

## 判定と固定

- 全プローブで「予測折り返し位置＝実機」→ フォント仮説を確定し、
  ビルド時に幅テーブル JSON を生成する方式へ移行、`CALIBRATED = true`。
- 1 箇所でも不一致 → フォールバック混在か仮説違い。不一致の文字を特定して
  フェーズ B に戻る（工夫して数値を手で曲げない）。
- 結果（数字・判定・スクショ台帳との対応）は本ファイルに追記して固定する。

## 進め方メモ

- スクショと入力文字列は `materials/` へ（README の台帳形式）。
- 1 スクショ 1 メッセージが理想（どの文字列のスクショか曖昧にならない）。
- フェーズ A の 4 枚だけで LIMIT としきい値模型の妥当性が判定できるので、
  まず A だけ先行で送ってもらうのでもよい。
