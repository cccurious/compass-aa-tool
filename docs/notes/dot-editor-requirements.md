# ドット打ちエディタ 要件定義（2026-07-25 ユーザー確定）

## 確定要件

| 項目 | 決定 |
|---|---|
| 描画方式 | 全角グリッド直置き（マス目に全角文字を置く） |
| キャンバス | **20 列固定**（実機 1 行の安全圏）× 行数可変。文字数の節約を最優先 |
| パレット | プリセット（■□●○◆◇▲△▼▽★☆・ω 等）＋自由追加（**幅 1.0 の全角文字のみ受理**） |
| 連携 | 「AA 変換へ送る」ワンタップで変換ビューの入力欄へ転送（変換ロジックは一本化） |

## 文字数節約の規則（コア変換 gridToText）

1. **行末（右端）の空セルは出力しない**。行末の全角スペースはパディングと重複するだけで
   表示に寄与しない（半角スペース帯が改行を作るため）。
2. 左端・中間の空セルは全角スペースとして出力（字下げ・隙間はキャリー仕様により保たれる）。
3. 全セル空の行は空文字列として出力（convert 側の空行処理＝全角スペース 1 個行が引き受ける）。
4. 末尾の全空行は削る（AA の下に無駄な行を送らない）。

## UI 要件

- グリッド: タップで選択文字を置く。ドラッグで連続塗り。消しゴム（空セル）あり。
- 行操作: 行追加・行削除・全消去。
- 文字数カウンタ: グリッド→gridToText→convert の出力文字数を常時表示（184 上限と超過警告）。
- スマホ優先: セルは画面幅 /20 で可変。タッチドラッグ対応（touch-action: none）。
- パレット自由追加: 1 文字のみ・charWidth(ch)===1.0 でなければ拒否（理由をトースト表示）。

## 実装構成

- `src/core/grid.ts` — gridToText（純関数・テスト対象）
- `src/core/palette.ts` — パレットのマスターデータ（幅 1.0 保証は門番テストが担保）
- `src/store/useDotStore.ts` — zustand（grid・palette・選択中文字）
- `src/components/views/DotEditorView.tsx` — 組み立てだけの薄い親。実体は
  `dot/PalettePanel.tsx`（パレット UI）・`dot/useCanvasGestures.ts`（1 本指描画／
  2 本指パン）・`dot/useZoomPan.ts`（2 倍表示とスクロールインジケータ）
- App.tsx — ビュー切替に 'dot' を追加・変換ビューの入力を App レベルへリフトして転送を実現
- Sidebar — 「ドット打ちエディタ」を有効化

## パレット改訂（2026-07-25 ユーザー確定・実装済み）

ドット絵に使える文字だけに絞り、カテゴリタブで切り替える方式にした（案 A）。

### 外した文字（12）

`● ○`（丸）`◆ ◇`（ひし形）`▲ △ ▼ ▽`（中央寄せの三角）`★ ☆`（装飾）`・`（点が小さい）`ω`（顔文字用）
— いずれも**隣のマスと繋がらない**ため、ドットの構成要素にならない。

### カテゴリ（全 73 文字・すべて実機で幅 1.0 検証済み）

タブは 3 つに統合し、先頭に「最近」を置く（2026-07-25 改訂）。

| タブ | 文字 | 用途 |
|---|---|---|
| 最近 | 直近に選んだ文字（最大 12） | 常用の出し入れ。**選び直しても並べ替えない**（ボタンが動くと押し間違えるため） |
| 塗り | `█▓▒░■□▀▄▌▐` `◤◥◣◢` `▘▝▖▗▚▞▛▜▙▟` | 濃淡・半分・セル全面の三角・4 分割（実質解像度 2 倍） |
| 罫線 | `─│┌┐└┘╭╮╰╯├┤┬┴┼` `━┃┏┓┗┛┣┫┳┻╋` | 細線（丸角つき）と太線 |
| 特殊線 | `┍┑┕┙┎┒┖┚┝┥┰┸` `═║╔╗╚╝╠╣╦╩╬` | 太細つなぎと二重線 |
| 追加分 | ユーザーが追加した文字 | 1 文字以上あるときだけ表示 |

### UI の掟

- タブは**折り返さず 1 段**（横スクロール）。折り返すとキャンバスが下へ押し下げられ、
  スマホで描きにくくなるため（実測: 折り返し 80px → 1 段 39px）。
  3 タブ構成なら 375px でスクロールも不要になった。
- パレットは**最大 3 段（138px）で内部スクロール**。文字数が増えてもキャンバスの
  位置が下がらないようにする（塗りタブは 5 段ぶんあるが表示は 3 段）。
- ボタンは 36px（375px 幅で 6 個/段）。「最近」の上限 12 はちょうど 2 段に収まる数。
- 文字を一括追加したら自動で「追加分」タブへ切り替える。

## 拡大機能の実機事故と修正（2026-07-25）

- **事故**: 2 本指タップ後にタッチ判定が残留し、以後 1 本指で塗れなくなる。
- **原因**: 1 本目の指で `releasePointerCapture` を呼んでいたため、指がグリッド外で
  離れると pointerup がグリッドへ届かず、指の記録（pointersRef）が残留。
  以後の 1 本指タッチが常に「2 本目」と誤判定されていた。
- **修正**（3 点）:
  1. **キャプチャは解除しない**。塗りは座標（elementFromPoint）で追うので
     キャプチャがあっても動き、あれば up/cancel が必ず届く。
  2. 指の記録の掃除は **window の pointerup/pointercancel** で行う（取りこぼし不能）。
  3. パン開始時、1 本目が塗ってしまったセルを **300ms 以内なら元に戻す**
     （2 本指のつもりでも 1 本目が先に着地して 1 マス塗ってしまうため）。
- 検証済み: 事故シナリオ（グリッド外で指を離す→次のタップ）で塗れること・
  誤タッチの取り消し・ドラッグ塗り・2 本指スクロールの全て。
- 教訓: **ポインタの生存管理はグリッド要素の上だけで完結しない**。
  指はどこでも離される前提で、掃除は window レベルに置く。

## 拡大の「見える化」（2026-07-25・案4採用）

「拡大したことが分かりにくい」との実機フィードバックに対し、モード自体は
維持して不可視な部分を全て見えるようにした（モード廃止案＝常時拡大は、
スマホでプレビューが画面外に出るため「全体を見る手段がキャンバスしかない」
という理由で棄却。等倍=全体ビューとして残す）。

- 幅の切替に 0.25s のアニメーション（切替の瞬間が見える）
- 拡大中はタイトル横に「2倍表示中」バッジ＋キャンバス枠がオレンジに
- ボタンは「拡大 ⇔ 等倍にもどす」で押下状態も色で表示
- 自前のスクロール位置インジケータ（iOS はスクロールバーを隠すため）。
  プログラム的なスクロールでは scroll イベントの発火が環境依存なので、
  パン処理側から直接更新する
- 拡大・縮小時は「いま見ている場所」の比率を保ってスクロール位置を合わせる

## 検討して見送り: 半角 0.5 グリッド（2026-07-25）

「グリッドを 0.5 刻みにして細かい調整を」という案を検討し、**見送り**とした。

### 決定的な壁: 「見えない 0.5」が実機に存在しない

グリッドの抽象は「どのセルも空にできる」ことが前提。空きセルは不可視の
スペーサーで埋める必要があるが、実機の不可視文字は
**全角スペース = 1.0 と半角スペース = 0.34 の 2 つだけ**で、
0.5 を作る組み合わせが存在しない（0.34×n は 0.5 の倍数に一致しない）。
つまり**行の途中に空の半セルがあるだけで、その行はレンダリング不能**になる。
さらに行頭の半角スペースは実機で消えるため、行頭インデントはどのみち
1.0 刻みのまま。「半セルは必ずペアで埋める」等の制約 UI は説明不能なほど複雑。

### 副次的な問題

- 0.5 ちょうどの文字は**半角カナ 63 字・_・∥ のみ**（実測）。ASCII 英数記号は
  プロポーショナル（0.22〜0.88）で格子に乗らず、「なぜ j は置けないのか」を
  ユーザーに説明できない。
- 40 列 × 375px = 半セル 8px。等倍タップは不可能になり拡大が必須化する。
- 純粋なドット絵の解像度需要は 4 分割ブロック（▘▝▖▗ 等）が既に充たしている
  （1.0 格子のまま実質 40×30 ドット）。

### 半角を活かしたい場合の代替（需要が出たら再訪）

1. **ペアセル方式**: 1 セルに半角カナ 2 文字（例「ﾉｼ」）を入れる。格子は 1.0 のまま
   崩れないが、片割れが空のペアは結局表現できない（同じフィラー問題に帰着）。
2. **AA 変換ビューへの往復**: テキスト編集なら半角もプロポーショナルも自由。
   「テキストで細かく調整する」ボタンが既にこの動線。

## 設計メモ: アンドゥ（未実装・2026-07-25 レビューで方針決定）

現状、2 本指パン開始時の誤タッチ復元は「ストローク開始セルの元値を 300ms だけ
覚えておいて書き戻す」という局所ハック（useCanvasGestures.ts）で済ませている。
本物のアンドゥを入れるときは次の形にする:

- ストローク単位で履歴を積む: beginStroke 時に grid のスナップショットを
  `history: DotGrid[]`（store 内・上限 50 件程度）へ push、undoLastStroke で pop。
  grid は行×20 の string 配列なのでスナップショットのコストは無視できる。
- これが入ったら 300ms 復元ハックは削除し、2 本指検出時は単に undoLastStroke を
  呼ぶ（「誤タッチの 1 マス」だけでなくドラッグで塗った複数マスも正しく戻る）。
- history は persist の partialize に**含めない**（描きかけの grid 自体を
  保存しない方針と揃える）。

着手の目安: 実機ユーザーから「消しゴムで戻すのが面倒」の声が出たら。
