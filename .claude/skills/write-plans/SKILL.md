# 判断確定版手順書の書き方（プロジェクト非依存の方法論）

手順書の目的は「**実行者が一切判断せずに完走できる**」こと。実行者は将来の自分・
別モデル・弱いモデルのいずれでもありうる。判断が 1 箇所でも残っていると、実行者は
そこで独自判断（＝品質事故）か停止（＝手戻り）する。書き手の仕事は判断の全消化である。

## 必須の構成（この順で）

1. **冒頭ブロック**: 作成日・作成者・対象（何を作るか 1 行）・確定済みの調査結論
   （実行者が再調査しないための「なぜ」の要約）・全体の掟（絶対条件）。
2. **番号つき項目**（1 項目 = 1 コミット）: 各項目に
   - 触るファイルと**実装アンカー**（「この関数のこの行の直後」まで特定する）
   - コードスケッチ（関数シグネチャ・定数値・数式は**確定値**で書く。「適宜」禁止）
   - UI 文言は**一字一句**（実行者に文言を作らせない）
   - その項目のテスト（何を assert するか具体的に）
   - コミットメッセージ（そのまま使える形で）
3. **完了の定義**: 全ゲート（テスト・lint・型）green ＋実測記録先＋目視項目の追記先。
4. **中止条件（キル条件）**: 「これが起きたら工夫せず止まって報告」を列挙する。
   最低限: 期待値を変えたくなった / 契約変更が必要になった / 同じ項目で 2 回失敗 /
   手順書と現実が矛盾。**キル条件のない手順書は手順書ではない。**
5. **スキップ規則**: 独立項目はスキップ可と明示（理由の記録を義務化）。
   一本道はスキップ不可＝中止条件扱いと明示。

## 品質判断が絡む場合の追加装備

- **合格ゲートを客観化する**: 「良くなったら」ではなく「合成の正解 K に対して
  バケット距離 ≤1」「全ゴールデンでビット同一」のような機械判定可能な数字にする。
  客観化できない審美判断は「ユーザーが A/B を目視して承認」と**手順として**書く
  （誰が・何を・どの道具で見るかまで）。
- **探索空間を閉じる**: knob 調整が要るなら候補集合を列挙し（例: r ∈ {0.07,0.08,0.10}）、
  「全滅なら不採用で終了」と書く。無限の試行錯誤を許さない。
- **見送り案の理由を固定する**: 採らなかった代替案と理由を書く（再訪条件つき）。
  これが無いと後続セッションが同じ検討を繰り返す。

## テクニック集（実績あり）

- **復元は commit 参照で**: 一度実装して撤去したコードは「git show <hash> で復元」と
  書けば手順書にコードを再掲しなくて良い（撤去コミットの逆適用）。
- **段階ゲート**: 「既定 OFF で実装（＝既存出力ビット不変で入れる）→ 評価 → 既定変更」
  に分解すると、品質判断を最後の小さな一歩に隔離できる。
- **予想を書く**: 「このケースに微差が出るはず／このケースは不変のはず。動いたら実装ミス」
  と予想を固定すると、実行者が異常を検知できる（самопроверка）。
- **影響テストの全数列挙**: 変更する既定値・出力パス・ラベル・順序を tests/ に grep し、
  赤くなりうる既存テストを手順書に列挙して「更新して良い（契約変更の反映）」と明記する。
  列挙漏れは実行者の中止→裁定往復を生む（実例 2026-07-12: 出力パス変更で
  test_gui_smoke が漏れ、実行が2回停止した）。
- **逸脱の記録を義務化**: 逸脱ゼロが理想だが、記録なき逸脱が最悪。手順書側に
  「逸脱は◯◯へ記録」と書いておく。
- **ビット同一リファクタは旧実装を恒久の参照実装にする**: 「結果を変えない高速化」の
  手順書には、旧実装をテスト内に `_ref` として温存し、新旧の**完全一致 A/B テスト**を
  恒久追加する項を必ず入れる（一時的な検証で捨てない）。将来の保守者が差分ロジックを
  壊したとき最初に赤くなる門番になる（実績: despill カーネル・背景色系差し替えの差分化。
  エッジケース——空集合・全滅経路——を A/B の入力に含めることまで手順書で指定する）。
- **素材・データの寸法/実値は書く前に実測する**: レイアウト定数や倍率など、素材の
  実寸に依存する確定値は ffprobe/PIL で測ってから書く。推測寸法で書いた手順書は
  実行者の停止→再裁定往復を生む（実例 2026-07-16〜17: 動画実寸の思い込みで
  B2/B0/B1 の 3 回停止。いずれも 1 コマンドの実測で防げた）。
- **文字列の物理幅は言語で変わる**: 同じスロットに JA/EN を流すレイアウトでは、
  固定フォントサイズでなく「上限幅＋超過時に等比縮小」のガードを最初から入れる
  （実例 2026-07-17: EN 見出しが右端で見切れ）。

## 書いてはいけないもの

- 「必要に応じて」「適切に」「様子を見て」——全部、消化しきれていない判断の白旗。
- 実行者への裁量移譲（「良い感じの名前で」）。名前も値も書き手が決める。
- 手順書内の未検証の事実（「〜のはず」で終わらせず、書く前に確認して確定させる）。
